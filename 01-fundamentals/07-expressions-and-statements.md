# Expressions and Statements

> **Status:** Syllabus outline. We will expand this lesson into teaching notes, a coding lab, exercises, and a small project when we study it.

## Learning objectives

- Distinguish an expression from a statement.
- Explain how expressions produce values and how statements perform actions.
- Read a short program as an ordered sequence of operations.
- Use assignment and expressions without confusing `=` with `==`.
- Recognize syntax errors versus errors that occur while a program runs.

## Sections

1. **Expressions** — literals, names, function calls, and combinations that produce values.
2. **Statements** — assignment and other instructions that form a program.
3. **Evaluation order** — how subexpressions and operators contribute to a result.
4. **Assignment is not equality** — binding a name versus comparing two values.
5. **Reading execution step by step** — tracing variable values through a short straight-line program.
6. **Syntax versus runtime behavior** — parsing failures versus problems encountered during execution.
7. **Readable expressions** — parentheses, intermediate variables, and avoiding unnecessarily clever code.

## Coding lab

Trace a short measurement-calculation script line by line. Rewrite a long expression into named intermediate steps and compare which version is easier to explain.

## Exercises

- Classify examples as expressions or statements.
- Trace values after each assignment.
- Find and explain an incorrect use of `=` or `==`.
- Improve an expression for readability without changing its result.

## Knowledge check

Explain the difference between an expression and a statement, and trace a short program without running it.
