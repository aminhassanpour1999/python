# Comments and Code Style

> **Status:** Syllabus outline. We will expand this lesson into teaching notes, a coding lab, exercises, and a small project when we study it.

## Learning objectives

- Write comments that explain intent rather than repeat obvious code.
- Use meaningful names and consistent formatting.
- Apply beginner-relevant PEP 8 conventions.
- Distinguish comments from string literals and docstrings at a basic level.
- Improve readability without changing program behavior.

## Sections

1. **Why style matters** — readability, maintainability, and fewer avoidable mistakes.
2. **Comments** — `#`, useful explanations, and comments that become misleading.
3. **Naming** — descriptive `snake_case` names for variables and constants.
4. **Whitespace and indentation** — four spaces, spacing around operators, and blank lines.
5. **Line length and layout** — keep simple scripts easy to scan; use the project's chosen conventions consistently.
6. **Strings, comments, and docstrings** — distinguish their purposes; formal docstring conventions are revisited with functions.
7. **Small refactors** — rename unclear variables, extract intermediate calculations, and remove redundant comments.
8. **Using style guidance wisely** — PEP 8 is a guide to readable code, not a substitute for correctness.

## Coding lab

Take a deliberately hard-to-read calculation script and refactor its names, spacing, comments, and output labels while preserving its behavior.

## Exercises

- Improve poorly named variables.
- Remove comments that merely restate the code and add one that explains intent.
- Find inconsistent spacing and indentation.
- Explain how readability helps debugging and collaboration.

## Knowledge check

Name three style practices you will use in every exercise and explain what makes a comment useful.
