# Programming Fundamentals

This module builds the working foundation needed to write, read, reason about, test, and debug small straight-line Python programs. It follows Introduction and prepares you for Control Flow.

## Learning outcomes

By the end of this module, you should be able to:

- Explain names, objects, values, assignment, rebinding, identity, and built-in scalar types.
- Perform numeric calculations and reason about precedence, complex numbers, bitwise operations, floating-point limitations, and numeric tools.
- Work with strings, literals, escapes, indexing, slicing, immutability, searching, transformations, formatting, and Unicode fundamentals.
- Convert and parse values deliberately; distinguish representation, validation, and formatting.
- Build simple terminal interactions using input() and print().
- Reason about truthiness, Boolean logic, short-circuiting, and None.
- Distinguish expressions from statements and trace straight-line programs.
- Write readable code using meaningful names, units, comments, and basic PEP 8 conventions.
- Diagnose syntax errors, runtime exceptions, and logic errors systematically.

## How to study each lesson

Follow the Learning Charter's study cycle:

1. Orient yourself to the goal and prerequisites.
2. Understand the concept and its mental model.
3. Predict example output before running code.
4. Type, run, modify, and deliberately test examples.
5. Attempt exercises without opening the solution file.
6. Debug errors using evidence and explain the repair.
7. Connect the concept to earlier lessons and practical code.
8. Complete the lab and review from memory.
9. Update learner progress only after independent demonstration.

## Content standard

The current written-material audit is recorded in [QUALITY-REVIEW.md](./QUALITY-REVIEW.md). It is a revision review, not a claim that all examples have been executed or that the learner has mastered the module.

A substantive lesson should include the relevant parts of:

- Learning objectives, prerequisites, and study guidance
- Conceptual explanations and precise terminology
- Syntax and semantics, including important distinctions
- Runnable examples and expected behavior
- Edge cases, common mistakes, and debugging guidance
- A coding lab with explicit acceptance criteria
- Independent exercises at increasing levels of difficulty
- Separate, explanatory solutions
- A knowledge check, summary, completion criteria, and reliable references

A lesson does not need unnecessary length or every possible detail. It must, however, explain all essential concepts at the depth required for independent use. Advanced internals are assigned to later modules rather than omitted from the curriculum.

## Module completion criteria

Before moving to Control Flow, you should be able to:

- Explain the concepts in all nine lessons without copying examples.
- Predict and explain unfamiliar expressions and short code snippets.
- Write a small command-line program using text, conversion, numeric operations, Boolean reasoning, and readable output.
- Test ordinary, boundary, and invalid cases.
- Read and diagnose beginner-level errors.
- Score at least 40/50 on the cumulative assessment.
- Review every missed objective and retry it without notes.
- Solve a new transfer task that is not copied from the assessment.

A passing score is necessary evidence, not an automatic mastery label. The roadmap's Demonstrated status requires independent performance and explanation.

## Scope boundaries

This module intentionally stops before teaching conditions and loops in depth, collections in depth, functions, robust exception handling, file I/O, modules, and object-oriented programming. Those topics have dedicated later modules. A short preview may be used when it clarifies a concept, but later features must not become hidden prerequisites.

This module is comprehensive for its intended stage, not a claim to teach all of Python or make a learner senior. Advanced language internals, software architecture, testing frameworks, concurrency, performance engineering, and production practices belong later.
